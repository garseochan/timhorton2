# 팀홀튼 한 잔의 여행 — 제안 시연판

index.html을 브라우저로 열면 실행됩니다. 네트워크와 설치가 필요 없습니다.

## 반영 내용
- 인트로 → 서울·경기 관광 도식 지도 → 32매장 윷놀이판 → 방문 결과·쿠폰.
- 제공된 32store 파일에서 매장명을 추출했습니다. 지도는 지역별 관광 도식이며 실제 지리 경계가 아닙니다.
- 33칸 연결 경로: 직사각형 외곽 20칸(출발 1칸 포함), 가운데 원 5칸, 대각선 8칸. 출발점 외에는 빈 칸이 없으며 한 칸 이동은 다음 매장(또는 출발점)까지 이동합니다. 32개 매장을 외곽 19개·원 5개·대각선 8개로 배치. 최종 착지 매장만 집계하며 같은 매장은 한 번만 셉니다.
- 기본 던지기 4회. 윷 띄우기 후 5초 안에 던지기. 시간 초과 시 1회 소모.
- 독립적인 윷 4개의 앞/뒤 조합으로 도/개/걸/윷/모 = 1/2/3/4/5칸.
- 매 게임 무작위 6매장은 +1회, 별도 8매장은 +1~3P. 각 매장 보너스는 최초 도착에만 적용.
- 윷·모 자체 추가 턴은 없음. 외곽 꼭짓점에 정확히 착지하면 팝업으로 대각선/직진 방향 선택. 최초 출발에는 팝업 없음. 마지막 기회 착지 시 광고 추가 기회를 받으면 팝업 표시. 가운데 원 연결 매장에 착지한 뒤 다음 던지기는 대각선으로 바깥쪽 자동 이탈. 대각선 이동 중 턴이 끝나면 다음 턴에도 같은 방향으로 진행.
- 0개 방문도 참여 쿠폰 예시 제공. 금액은 임시 1,000원 할인.
- 공유 버튼은 실제 메시지를 보내지 않으며 +5P 결과를 시연합니다.

## 운영 전 작업
이 패키지는 독립 제안 시연판이며 오글오글 업로드 완료본이 아닙니다. 실제 지급 기능은 없습니다.
오글오글 개발 스킬의 owner 경계를 참고했으며 운영 전 다음 연결이 필요합니다.
1. 승인 mock block 및 bridge ready bootstrap, login.check, participation.getState.
2. execution.report START/COMPLETE/ERROR 및 서버 검증.
3. 등록된 POINT_TRIGGER 정책으로 실제 포인트 판정. 브라우저 난수로 실제 혜택 지급 금지.
4. 게임 내 던지기 횟수와 서버의 참여 횟수를 분리.
5. 쿠폰 benefit 정책 및 발급 결과 연결.
6. share.requestKakao와 wrapper의 공유 완료·보상 상태 반영. 요청 성공만으로 5P 지급 금지.
7. 실제 매장 위치·운영 여부, 브랜드 자산, 쿠폰 조건 확정 후 업로드 검사.

## 보드 모션
윷은 별도의 배경 없이 판 위에서 CSS 3D 회전·상승·낙하·바운스 모션을 사용합니다. PNG 파일 없이 투명 배경 효과를 구현했습니다. 동작 줄이기 설정 시 모션을 생략합니다. 작은 화면에서는 매장명 가독성을 위해 판을 좌우 스크롤합니다.

## 매장 번호
1 미금역 → 2 분당서현 → 3 야탑역부터 외곽 직사각형 진행 순서로 1~19번. 대각선은 출발 쪽 → 오른쪽 위 → 왼쪽 위 → 왼쪽 아래 순서로 각 바깥에서 안쪽으로 20~27번. 가운데 원은 위쪽부터 시계 방향으로 28~32번. 지도 목록에도 동일한 번호를 표시합니다.


## 포인트·이어하기 미션
포인트 획득 시 금액 팝업을 먼저 보여주고 확인 후 방향 선택 또는 기회 소진 팝업을 표시합니다. 중복 방문에는 포인트 팝업이 다시 뜨지 않습니다.
기회 소진 시 하기/그만하기 선택. 광고는 제거하고 커피 취향 선택 미션 3개로 교체했습니다. 각 미션 선택 완료 시 +2회, 최대 +6회. 취소·중복 클릭 시 지급 없음. 위치와 방문/포인트 유지. 선택값을 저장하거나 전송하지 않습니다. 모두 소진하면 결과로 안내합니다. 완주 보장이나 별도 완주 보상은 구현하지 않았습니다.
